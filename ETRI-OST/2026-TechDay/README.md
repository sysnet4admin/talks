## 무엇을 이야기하나

MCP가 2024년 11월에 나왔을 때 푼 문제는 연결이었습니다. 모델마다 도구를 따로
이어야 해서 모델 3개에 도구 4개면 연결이 12개였는데, 가운데 규약을 하나 두니
7개가 됐습니다.

그런데 서버를 여러 대로 늘리면 다른 문제가 생겼습니다. 세션이 프로세스 안에 있어서
요청을 아무 대에나 보낼 수 없었습니다. 1대가 죽으면 그 안의 세션도 같이 사라졌습니다.
세션 관리 코드는 구현마다 제각각이었습니다.

**2026년 7월 28일 개정이 그 세션을 스펙에서 뺐습니다.** initialize 핸드셰이크도
Mcp-Session-Id도 없습니다. 요청 하나에 필요한 정보가 다 들어갑니다. 어느 서버가 받아도
그 요청만 보고 처리합니다. 원격 MCP 서버를 평범한 웹 서비스처럼 운영할 수 있게
됐습니다.

발표는 그 전과 후를 나눠서 봅니다. 과거는 탄생부터 전환까지, 현재는 스펙이 바꾼
것과 두 달이 지난 지금의 생태계, 미래는 방향만 짧게 다룹니다.

## 라이브 데모

말로 설명하지 않고 터미널에서 실제로 돌립니다. 네 단계가 전부 같은 것을 두 번 보고
무엇이 달라지는지 보는 구조입니다.

| 단계 | 하는 일 | 달라지는 곳 |
|---|---|---|
| 1 | 서버 코드를 봅니다 | 4대가 같은 파일이고 플래그 하나만 다릅니다 |
| 2 | 세션 헤더 유무로 부릅니다 | 같은 호출 4번 중 구 스펙만 한 번 막힙니다 |
| 3 | 서버를 죽입니다 | 예비가 남았는데 구 스펙만 끊깁니다 |
| 4 | MCP를 붙입니다 | 모르던 것을 답하고 값까지 바꿉니다 |

서버는 76줄이고 도구가 2개입니다. 조회하는 `get_project` 와 값을 바꾸는
`update_project` 입니다. 클라이언트는 goose, 모델은 로컬 ollama라 외부 API를
부르지 않습니다.

준비와 실행 방법은 [DEMO/README.md](./DEMO/README.md)에 있습니다.

```bash
cd DEMO
./scripts/0.setup_before.sh   # 서버 4대, 모델, venv 준비
./scripts/watch_calls.sh      # 왼쪽 터미널
./scripts/1.demo.sh           # 오른쪽 터미널
```
