# OST 2026 데모

「MCP, 7월 28일 이전과 이후」(ETRI 오픈소스 테크데이 2026, 10/7) 발표의 라이브
데모다. 발표 슬라이드 p14~p16 구간에서 약 5분 동안 돌린다.

## 무엇을 보이는가

**2026-07-28 개정으로 원격 MCP 서버를 평범한 웹 서비스처럼 운영할 수 있게 됐다**는
것이 이 발표의 주장이다. 데모는 그것을 세 박자로 보인다.

1. 같은 도구를 4번 호출한다. 세션 헤더만 다르다. 구 스펙에서 헤더가 없을 때만
   과제명이 안 뜬다
2. 양쪽에서 1대씩 죽인다. 둘 다 예비로 넘어가는데 구 스펙만 거절당한다
3. 죽인 서버를 다시 띄운다. **구 스펙은 `Session not found`로 남고 신 스펙은
   돌아온다.** 세션이 죽은 프로세스 안에 있었고 클라이언트가 initialize부터 다시
   해야 하기 때문이다

3번째가 이 데모의 결론이다. 슬라이드 p6이 말한 세 가지 문제(요청 분배, 장애
복구, 세션 코드 직접 구현)가 왜 없어졌는지를 한 화면에서 보여 준다.

## 네 단계

| | 무엇에 답하나 | 시간 |
|---|---|---|
| 1 서버 코드를 봅니다 | 서버가 얼마나 짧고 두 스펙이 무엇으로 나누어지나 | 45초 |
| 2 세션 헤더에 따라 동작이 달라지는지 봅니다 | 세션 헤더가 있고 없고가 무엇을 바꾸나 | 30초 |
| 3 서버를 죽입니다 | 1대가 죽으면 어떻게 되나 | 60초 |
| 4 MCP를 붙이기 전과 후를 봅니다 | 붙이면 무엇이 달라지나 | 2분 35초 |

**4단계도 대비다.** 같은 명령을 2번 실행하고 두 번째만 옵션이 하나 붙는다. 명령이
같아야 답이 달라진 이유가 옵션 하나로 좁혀진다.

끝에 읽고 쓰고 다시 읽는 세 칸이 붙는다. 조회만 하면 검색해서 문맥에 넣는 것과
모양이 같다. 그러면 도구가 값을 바꾼다는 것이 안 보인다.

| | 무엇 | 누가 | 시간 |
|---|---|---|---|
| 읽기 | `get_project` 로 과제를 물어본다 | 에이전트 | 6.5초 |
| 쓰기 | 단계를 바꿔 달라고 말한다 | 에이전트 | 4.6~8.9초 |
| 다시 읽기 | 서버에 남았는지 본다 | curl | 0.04초 |

도구 이름은 사람이 말하지 않는다. 프롬프트에는 과제 코드만 있다. 어느 도구를 쓸지는
2단계에서 화면에 띄운 `description`과 `inputSchema`를 읽고 에이전트가 정한다.

**다만 이 단계가 보이는 것은 MCP 일반이지 2026-07-28 개정이 아니다.** 7/28과 관련된
곳은 `mcp.json`에 세션 관리가 없다는 것 하나다.

## 구성

```
server/ost_server.py          도구 2개짜리 MCP 서버. 76줄
client/mcp.json               goose 설정. 8줄
scripts/0.setup_before.sh     초기화 8단계
scripts/1.demo.sh             오른쪽 터미널. 엔터로 한 단계씩
scripts/show_code.sh          서버 코드를 구간별로 띄우고 색을 입힌다 (1단계)
scripts/show_servers.sh       4대가 같은 파일임을 프로세스로 보인다 (1단계)
scripts/list_both.sh          세션 헤더 유무로 두 스펙에 4번 호출한다 (2단계)
scripts/diff_reply.sh         두 응답에서 다른 곳만 짚는다 (2단계)
scripts/read_stage.sh         과제 1건의 단계를 curl 로 읽는다 (4단계)
scripts/watch_calls.sh        왼쪽 터미널. 두 스펙에 계속 호출
scripts/9.cleanup.sh          서버 정리
```

**서버 3대가 같은 파일 하나다.** `ost_server.py`가 `PORT`와 `STATELESS`를
환경변수로 받는다.

| 포트 | `stateless_http` | 무엇 |
|---|---|---|
| 8100 | `False` | 구 스펙. 세션을 만들어 요청 사이에 저장한다 |
| 8101 | `False` | 구 스펙 예비 |
| 8200 | `True` | 신 스펙 |
| 8201 | `True` | 신 스펙 예비 |

**포트 번호는 아무 주장도 하지 않는다.** 81xx와 82xx는 백의 자리 하나만 달라서
화면에서 두 열이 짝으로 보이라고 붙인 값이다. 스펙 이름이 2.0인 것은 아니다.
리비전 이름은 `2025-11-25`와 `2026-07-28`이고 2.0은 SDK 패키지 버전이다.

구 스펙 쪽 리비전이 `2025-11-25`인 것은 서버가 직접 답한 값이다. 그 서버에
`2026-07-28`로 initialize를 걸면 `2025-11-25`로 내려서 합의한다. 세션이 있던
마지막 리비전이 그것이다.

**`stateless_http`는 7월 28일에 새로 생긴 것이 아니다.** 구 계열 SDK(`mcp` 1.30.0)
에도 있었고 기본값이 `False`였다. 다만 스펙이 세션을 요구했으므로 켜면 규격 밖이었다.
2026-07-28 개정이 한 일은 이쪽을 표준으로 삼은 것이다. 데모 문구도 "7월 28일에 생긴
것"에서 "개정으로 표준이 됐다"로 고쳤다(2026-09-14).

**양쪽을 2대씩 둔다.** 한쪽만 2대면 "2대가 1대보다 잘 버티는 건 당연하다"가
된다. 그러면 이 데모가 보이는 것이 스테이트리스가 아니라 이중화다. 클라이언트도
양쪽에 같은 규칙을 쓴다. 실패하면 다른 대로 넘긴다. 서버 수도 같고 클라이언트
동작도 같으니 남는 차이는 플래그 하나뿐이다.

## 실행

터미널 두 개가 필요하다. 왼쪽이 증거 화면이고 오른쪽에서 진행한다.

```bash
./scripts/0.setup_before.sh     # 준비. 전부 갖춰져 있으면 10초
./scripts/watch_calls.sh        # 왼쪽 터미널 (Ctrl+C 로 종료)
./scripts/1.demo.sh             # 오른쪽 터미널
./scripts/9.cleanup.sh          # 끝나고 정리
```

`0.setup_before.sh`는 없으면 만들고 있으면 건너뛴다. 처음부터 시작하면 모델
내려받기까지 20분을 넘는다. **무대 직전에 한 번 더 실행하면 모델 워밍이
갱신된다.** 기본 유효시간은 30분이고 `OST_KEEP_ALIVE`로 바꾼다.

## 2단계가 보이는 것

```
  보낸 요청  get_project("2026-AI-013"). 4번 다 같은 요청이고 세션 헤더만 다릅니다

**HTTP 코드가 아니라 과제명이 뜨는지로 보인다.** `tools/list`로 개수를 세면 숫자
보고가 된다. `tools/call`로 실제 일을 시키면 결과가 나오거나 안 나온다. 청중은
코드를 해석하지 않고 데이터가 있는지만 본다.

**4번을 다 보여야 호환 규칙이 읽힌다.** 한 줄만 보이면 "구 스펙은 실패, 신 스펙은
성공"에서 끝난다. 4번을 다 보이면 방향이 나온다. 구 스펙 서버는 세션 헤더를
요구하고 신 스펙 서버는 있어도 없어도 일한다. 그래서 **구 스펙 클라이언트는 신 스펙
서버에 붙지만 반대는 안 된다.** 덱 p13의 "신 스펙 전용과 구 스펙 전용이 만날 때만
실패"가 이 방향이다.

신 스펙 서버는 `initialize`를 받아도 `Mcp-Session-Id`를 주지 않는다. 아무 값이나
붙여 보내도 그대로 받는다(2026-09-14 확인).

**응답에서 다른 곳은 헤더 한 줄뿐이다.**

```
  응답 헤더
      cache-control: no-cache, no-transform
      connection: keep-alive
      content-type: text/event-stream
    - mcp-session-id: 7e50e1c594d149198c909f66aa6e5ef4   ← 구 스펙에만
      x-accel-buffering: no
      Transfer-Encoding: chunked

신 스펙 응답만 전부 보여 주면 구 스펙과 무엇이 다른지 알 수 없다. `diff`로
짚으면 바뀐 것이 세션 하나라는 것이 보인다.

## 색

데모 전체에서 색은 한 가지 뜻으로만 쓴다. **구 스펙을 늘 먼저 둔다.** 코드 주석,
서버 목록, 띄우는 순서, 죽이는 순서, 문서 표가 모두 구 스펙부터 간다.

| 색 | 뜻 |
|---|---|
| 노랑 | 구 스펙 2025-11-25 |
| 초록 | 신 스펙 2026-07-28 (그리고 호출 성공) |
| 빨강 | 호출 실패 |
| 청록 | MCP 서버를 만들고 실행하는 줄, 포트 번호 |
| 자주 | 도구 정의 (1단계 코드 화면에만) |
